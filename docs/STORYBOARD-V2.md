# 套圖規劃 v2：先免費預覽，再決定是否生圖

## 這次修正的問題

v1 的圖片指令未使用每張文案的用途，所有照片都被要求同角度、完整商品、置中；「智慧匹配」只切換上下圖文。這造成付費產出仍接近同一張商品照，詳情頁缺少閱讀節奏。

來源影片先規劃每張圖片的用途，並展示場景、細節、材質等不同畫面；範例也有三個角度參考圖。本 App 目前仍接受一張原圖，因此不能把未拍到的角度當成已確認的商品細節。

## 新的分工

| 用途 | 畫面 | 照片來源 |
|---|---|---|
| 商品主圖 | 保留完整商品照片 | 原圖，不重複呼叫模型 |
| 主視覺 | 大幅商品、較大標題、立體視覺方向 | 免費用原圖；明確同意後才生成新場景 |
| 賣點 | 獨立圖文模組，依文案量調整密度 | 原圖 |
| 原圖細節 | 大圖＋局部拼圖，可選上／中／下方 | 原圖裁切，不生成新材質或標籤 |
| 使用情境 | 場景占主要面積，文案獨立排版 | 範例用已存在的場景；上傳圖免費模式為情境構圖示意 |
| 規格 | 結構化資訊表、小型商品照片 | 僅使用已提供資料，未知資訊保持未知 |
| Banner | 橫幅構圖 | 優先共用本套主視覺照片 |

`CopySection.role` 與 `visualGoal` 現在會影響照片規劃和版型。每張可選用途、修改文字及畫面方向。舊文案可按「補齊 5 種用途」加入缺少的畫面，保留原內容。

## 零付費驗證範圍

本輪沒有呼叫使用者的 Gemini、Vertex 或 Veo API，也沒有另行使用 imagegen 產生新照片。

- 免費文案規劃在瀏覽器執行，不打 `/copy`。
- 免費預覽與圖片輸出在 Canvas 執行，不打 `/image` 或 `/video`。
- 使用者上傳的照片絕不替換為其他商品的範例場景。
- 主圖、細節、賣點、規格不重複生圖。
- 主視覺與 Banner 的相同場景會共用。完整預設套圖預計 2 次新照片請求，而非每張都生一次；這是呼叫數，不是價格承諾。
- 新的付費照片方向只經合約與模擬回應測試，沒有以付費模型驗證品質。

## 防止誤用金鑰

前端每次付費規劃／生成都需要明確勾選確認。確認不會寫入草稿；重載或改設定後不保留同意。

後端要求 `allowPaid: true`，否則回應 `PAID_CONFIRMATION_REQUIRED`。測試後端設定 `MONO_DISABLE_LIVE=1`，即使有金鑰和確認，也拒絕模型呼叫。直接 provider 函式同樣有停用檢查。

`playwright.preview.config.ts` 使用獨立本機連接埠，封鎖瀏覽器外部請求。照片共用案例使用明確攔截的靜態回應，不會抵達 Google。真實模型測試另須明確設定 `E2E_ALLOW_PAID=1`，本輪沒有啟用。

## 使用方式

1. 既有商品先返回文案，按「補齊 5 種用途」。
2. 檢查每張的用途和文案，再進入視覺設定。
3. 先看「免費套圖預覽」。
4. 按「免費預覽並下載」；免費模式則按「開始生成」。
5. 只有需要新場景且願意支付費用時，再使用明確的付費選項。

目前免費模式能驗證版型、裁切、下載與排版，不代表新 AI 場景品質已經驗收，也不能憑一張原圖還原未拍到的商品角度。

## 乾淨環境補充驗證

GitHub 首輪回歸發現：範例照片仍在下載時，下一步可被提早點擊。已把下載與圖片解碼納入同一段載入狀態，完成前停用下一步。新增測試會扣住圖片回應，確認按鈕停用，再釋放照片驗證可繼續。免費套圖測試會獨立執行，不因其他案例失敗而整組略過。
