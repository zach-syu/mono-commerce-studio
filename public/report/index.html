重要金鑰放哪裡？

Google 模型金鑰與 Supabase service-role 金鑰只由後端使用。前端只有公開 API 網址與 PostHog 事件寫入 token。工作室存取碼是登入用的短暫分頁記憶體，不是 Google 金鑰。

要讓雲端完整使用真實模型

  1. 由個人 Supabase 帳號設定模型 Secrets 與工作室存取碼。現有 Gemini Developer Key 不能直接當成 Vertex 憑證。
  2. 若使用影片，再設定標準 Vertex 專案、IAM 權限與可更新的存取憑證。
  3. 重跑相同雲端 E2E，核對真實 provider、圖片、紀錄與下載。正式多人服務還需登入、個別額度及權限驗收。

測試後的發現

  • 流程與模型品質分開驗證。真實模型案例保留原始回傳圖與最終成品，供應商為 gemini-api。其他示範案例的供應商為 demo-compositor 或 demo-slideshow。兩者不混用成功結論。示範商品原圖是先前由 AI 產生的測試素材，並非這次瀏覽器操作時呼叫模型。
  • 原圖與輸出都留下證據。21 項案例留下原始商品圖與雜湊。原圖一致性可以比對，但完整產品造型與實際規格仍需商家確認。
  • 文字需要一個可見的修正迴路。長文案測試檢查省略提示及全文保留；下載包同時有 copy.txt 與 manifest.json，可追蹤編輯內容。
  • 此次記錄沒有失敗案例。這只適用於本頁已執行的案例與環境，不代表所有平台與真實模型情境已驗證。

下一步建議

  1. 若要啟用雲端真實模型，填妥 Supabase Secrets 後，以相同商品與語言矩陣重跑雲端測試，保留 provider、model、duration 與每次錯誤。
